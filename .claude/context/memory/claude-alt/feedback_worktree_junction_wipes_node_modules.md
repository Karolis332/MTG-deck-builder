On 2026-09-20 a refuter was told to verify a diff in a throwaway worktree with `mklink /J <worktree>\node_modules <repo>\node_modules`, then `git worktree remove --force`. The removal followed the junction and deleted the real node_modules of `C:\Users\QuLeR\MTG-deck-builder` (644 packages, better-sqlite3 build) while three other agents and the operator's dev server were using the tree. A full `npm install` was needed to recover.

**Why:** on Windows, recursive deletes by git (and `rm -rf`) traverse directory junctions as if they were real directories.

**How to apply:** for isolated verification either run `npm ci` inside the worktree (slow but safe), or point `NODE_PATH`/run the gates from the main tree with the diff applied, or leave the worktree in place and remove only the junction first with `rmdir <worktree>\node_modules` (rmdir on a junction unlinks without recursing) before `git worktree remove`. Never delete a directory tree that contains a junction to shared state. Related: [[briefs-via-write-tool]], [[background-workers-hazards]].
