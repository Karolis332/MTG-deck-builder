**KEY FINDING — hold-one-out Hit@K is the WRONG primary metric for this engine.** Popularity baseline (recommend most-included cards) CRUSHES CF on hold-one-out: @30 Hit 94.6% vs CF 59.0%, MRR 0.69 vs 0.16. Not a bug — Commander decks share a huge staple core; the metric rewards predicting staples, but CF deliberately SUPPRESSES staples to surface synergy. So CF's absolute numbers are NOT "bad"; the nightly eval is a regression SENTINEL (catch drops), not a quality score. To fairly score CF, need a non-staple-restricted recall metric and/or engagement metrics.

**RESOLVED (non-staple metric built, GitHub 88e7060):** added `--staple-threshold` (default 0.40) + a non-staple metric family (`_ns`, excludes staples from the hidden set) to evaluate.py; nightly auto-saves it (CF --save). Verdict: on synergy cards CF DOMINATES popularity, esp. top-of-list — non-staple @10 Hit CF 32.0% vs pop 7.6% (4×), NDCG 0.083 vs 0.007 (~12×), MRR 0.159 vs 0.039 (4×); converges by @30. So the CF model IS sound; staple suppression works as designed; the earlier "CF loses" was purely the staple artifact. CF's non-staple≈all-card numbers confirm its recs are already non-staple-dominated. Headroom remains (non-staple R@30 ~0.185). Next levers: event logging (engagement), commander-conditioning in recommend() (currently color-identity-only), PMI/lift synergy scoring.
